# ASS v0.1.25

## 界面

- 修复深色模式中客户端列表仍显示浅色背景、菜单文字看不清的问题。
- 统一账户状态、提示、开关圆点、思维强度滑块和表单选项的深浅配色。
- 顶栏与主体使用一致底色；保留 Windows 原生最小化、最大化和关闭按钮，以及独立拖动区域。
- 窗口顶栏跟随手动主题和系统主题变化；弹窗和滚动区域避开顶栏。

## DSH 接入

- 识别桌面实际运行的 core 版本和 profile，不再将旧源码目录的版本当作当前运行版本。
- 适配 DSH 0.1.7-rc.2 的 `profiles/<profile>/cordis.patch.yml`；旧版仍使用 `settings.yaml`。
- 检测旧接入记录与新配置格式不一致的情况，显示迁移提示，避免把旧文件一致误报成新版接入正常。
- “一键修复”会先保存加密备份，再迁移最后一次实际接入的字段和托管记录；不将尚未确认的供应商修改一起应用。
- 已复制到新 profile 的相同字段可以接管；遇到同名但不同的供应商、并发修改或无法安全解析的表达式时停止，不覆盖个人配置。
- 同步适配模型目录读取、模型诊断及独立账户的配置；迁移后仍可正常撤回 ASS 接入。
- 不终止或重启 DSH；已经打开的 DSH 页面可能需要刷新模型目录。

## Codex 可选强制重启

- 开启、同步、关闭接入及“一键修复”提供“仅应用配置 / 强制重启”两档，默认不重启；只在本次确认中生效。
- 单独操作 Codex 并选择强制重启时，先关闭已验证的桌面进程树、取消 Codex 的代理请求，再应用配置并重新打开。OAuth 登录与会话文件保留。
- 不取消其他客户端或诊断请求。关闭最后一个路由接入时，如仍有其他请求，会在关闭 Codex 前提示等待。
- 进程身份变化、配置被并发修改、安装版本变化或重新启动失败时分别停止并提示，不把配置成功误报成重启成功。
- 本次开发与验证没有重启真实 Codex；进程关闭/启动使用隔离模拟，真实桌面入口只做只读识别。

## 验证

- 单元测试覆盖新旧格式、迁移与撤回、已迁移目标、独立账户、并发修改拒绝和凭据保留。
- 强制重启测试覆盖执行顺序、请求范围隔离、取消与默认选择、失败提示及 OAuth 保留；弹窗在隔离桌面实例中验证。
- Windows 打包窗口检查五个主页面、七个客户端面板及账户/供应商/模型弹窗，覆盖深色和浅色主题。
- 本机 DSH 模型目录已返回迁移后的 5 条协议路由、17 个注入模型及保留的原生模型，无目录加载错误。该检查不等同于逐个模型完成真实推理测试。

更新后请退出旧 ASS 窗口，再打开新版本。若 DSH 提示旧接入未迁移，在客户端页点击“一键修复”即可迁移 ASS 的托管记录，不必重启 DSH。
