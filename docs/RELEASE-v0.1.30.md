# ASS v0.1.30

## CC 终端免登录

- 修复无账号开关只影响 ASS 独立窗口的问题：CC 开启后写入其原生用户配置，系统终端直接运行 `claude` 也能使用注入模型。
- 本地网关凭据、模型列表与首次启动状态一起应用；真实供应商密钥不写入 CC，官方 OAuth 文件不删除。
- 关闭模式、断开 CC 或安全退出时，只还原 ASS 管理的字段；用户后续添加的设置、目录信任及原登录保留。
- 识别 `CLAUDE_CONFIG_DIR`，不把账户导入搜索目录当作终端配置目录；已发现的环境覆盖、组织登录限制、损坏配置会阻止启用。
- 写入和恢复使用加密事务记录；外部改动显示异常，可一键修复。旧版已开启的模式需先同步，界面不会把未迁移配置显示为已就绪。
- CC 开启前确认客户端版本支持自定义模型列表。仍保留正常目录信任和工具权限确认，不覆盖组织策略。

## 开关作用范围

- CC 和 Codex 分别控制，互不改动另一客户端的认证及模型配置。
- CC：新终端直接运行 `claude` 生效，ASS 需保持运行。
- Codex：写入桌面端使用的全局 provider、独立本地凭据与注入模型目录；已运行窗口仍需重启，未自动关闭用户任务。
- 两端出现字段变动、未同步时，不再只显示启用成功；关闭后恢复之前的认证方式。

## 验证

- 460 项自动测试通过，涵盖字段恢复、OAuth 保留、事务回滚、重启恢复、旧版本迁移、外部改动与两端开关隔离。
- 本机 Claude Code 2.1.283 在隔离原生目录下直接执行 `claude`：无官方登录，完成目录信任后进入交互会话，收到模拟接口回复。`/status` 确认认证和地址来自原生用户设置；`/model` 仅列出注入模型及指向该模型的默认项。
- 使用 Codex 桌面 App 自带后端、全新无 `auth.json` 配置，经实际 ASS 路由得到模拟接口回复；`app-server` 读取 provider 为 `ass_router`，模型列表仅含注入模型。
- 独立 Electron 窗口实测开启、确认、重启持久化、分别关闭与原生字段恢复；无前端控制台错误。
- 没有重启用户真实 Codex/CC 窗口，未切换当前真实账户；Codex 桌面已有会话的界面重载不作为已验证结果。未使用真实供应商付费请求。

## 使用

打开新版 ASS，在“客户端与账户”选择 CC 或 Codex，先同步模型接入，再开启无账号启动。CC 新开终端即可；Codex 等任务结束后重启，或在确认窗口明确选择强制重启。

终端自定义环境、项目设置或命令行参数可能覆盖用户级配置；ASS 不篡改这些外部设置。遇到异常先检查接入状态和 CC 的 `/status`。

依据：[Claude Code 网关配置](https://code.claude.com/docs/en/llm-gateway-connect)、[CC 设置优先级](https://code.claude.com/docs/en/settings)、[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。
