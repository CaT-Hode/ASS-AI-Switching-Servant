# ASS v0.1.19

客户端换过的 OAuth，现在可以自动记住并切回来。

- Codex / Claude Code / pi 的文件型 OAuth 在 ASS 运行时后台检测，加密保存新登录；支持原生目录与 ASS 独立授权目录。Codex 同一用户与工作区的令牌刷新更新已有卡片，不重复建账户。
- 账户卡片区分“当前账户”与“已保存账户”。“切换账户”经简短确认后写入原生 OAuth 凭据，先保留当前登录；不只是设置下次启动偏好，不重启或结束客户端进程。
- API Key 不进入 OAuth 历史。pi 只改选定服务，保留其他授权与 API 配置；Codex 系统密钥库、自动/内存凭据、环境变量覆盖等情况拒绝文件切换。
- 切换绑定文件与授权版本，确认期间被原生客户端修改则拒绝覆盖。历史与写前恢复事务整体使用 Windows DPAPI 加密，不向前端或发布包暴露令牌。后台状态有顺序保护，旧 IPC 回包不覆盖新的登录状态。
- 包含此前的客户端布局重整：左侧客户端、右侧供应商接入和账户；供应商整组开关，展开查看模型；移除启动模型和逐模型接入选项。未识别客户端折叠，路由总览只展示已识别的；账户卡片正确保留已查询的订阅额度。
- 开启、同步、关闭接入时可勾选“立即重启”，每次默认关闭。只自动重启已可靠识别的 Codex Store 桌面端 / OpenCode Desktop；操作会强制结束所选客户端的任务。安装入口或进程发生变化时拒绝自动重启，CLI 与不明确的实例仍需手动处理。配置成功但重启失败时明确区分结果。

请先结束客户端任务再切换账户。已经运行的窗口可能缓存旧授权，必要时自行重启。无法恢复 ASS 开始监测前已经覆盖的账户，也无法让服务端已撤销的授权重新有效。身份不可确定的 opaque 授权保守保留独立记录。

升级：从托盘退出旧版，完整解压新包运行 ASS.exe；原数据目录不变。验证使用隔离合成凭据，没有切换用户当前登录或发送付费模型请求。当前适配仍为 Codex、Claude Code、OpenCode、pi、DSH，新增其他 harness 不在本次完成范围。

参阅 [OAuth 历史说明](https://github.com/CaT-Hode/ASS-AI-Switching-Servant/blob/main/docs/OAUTH-HISTORY.md) 与 [验证范围](https://github.com/CaT-Hode/ASS-AI-Switching-Servant/blob/main/docs/VALIDATION.md)。
