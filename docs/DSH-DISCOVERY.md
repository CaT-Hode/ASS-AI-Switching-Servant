# DSH 本机扫描

v0.2.19 修复选择便携启动器后仍仅扫描 `~/.dsh` 的问题。目录识别从当前选中的启动入口出发，不写入某台设备的安装路径，也不将推断路径保存为手动覆盖。

- 客户端设置中明确选择的凭据目录优先。
- 读取启动器中可静态确认的 `DSH_HOME`。支持 CMD / BAT 的绝对路径、`%~dp0` 与已知环境变量，PowerShell 的字符串、`$PSScriptRoot` / `$env:变量`，以及 shell 的字面路径和已知环境变量。
- 无条件赋值会覆盖继承的 `DSH_HOME`；CMD 的 `if not defined DSH_HOME` 则保留已有环境值。
- 启动器未声明目录时，使用继承的 `DSH_HOME`，或在当前安装目录、入口目录及 `bin` / `node_modules/.bin` 的安装根目录检查已有 `.dsh` 状态。普通 npm shim、无 DSH 状态的同名目录不会被当作便携数据。
- 默认用户目录仍参与只读扫描。多个目录的账户保留来源信息；接入时仅认定当前有效目录中的原生 API，其他目录的账户不会冒充当前接入。

凭据扫描、官方 API / 模型识别、原生接入配置、对话来源及续聊目标共用此目录解析。扫描下一次操作重新读取启动器和凭据，移动目录或删除 Key 后不会沿用旧结果。

启动器只作有大小限制的文本读取，不执行脚本、命令替换、密钥助手或客户端。动态表达式、缺失变量和冲突赋值会显示“数据目录无法静态确认”，接入配置拒绝在猜测的目录写入；用户可在客户端设置中明确指定目录。识别本地 Key 只表示配置存在，不代表远端授权或余额已经验证。

DSH 的 `version: 1` / `refs` / `records` 及默认凭据位置参照[官方凭据说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/credentials/credentials-local/README.md)。未知插件授权记录不作为 API Key。

验证包含重新命名的安装目录、中文与空格路径、不同启动器、覆盖优先级、普通 shim、动态声明、入口变化和 Key 删除；合成凭据用于发布包 UI 检查，本机实际目录仅只读核对。
